# 13: Publish JSON Schemas for the output and validate every built file

**What to build:** The shapes of the static JSON become machine-readable. JSON Schema files, one per file type, are generated from the contract module (ticket 12) and committed at the repo root, so anything outside the backend (the frontend, a future Dagster job) can read the contract without reading Python. The fixture build is validated against them file by file. Requested 2026-10-19.

**Blocked by:** 12 (Gather the output contract into one backend module).

**Status:** resolved

- [x] A backend command writes one JSON Schema per file type (meta, locations, index, scanners, product, code scans), with shared rows as reusable definitions and field docstrings carried into descriptions.
- [x] The committed schemas are regenerated by that command; a test fails when they are out of date with the contract types.
- [x] Schemas are strict: required fields are required, nullable fields are explicitly nullable, and unexpected fields are rejected.
- [x] A build test validates every file written by the fixture build against its schema, including a URL-like code, an unknown product (`product: null`) and a scanner with no last scan.
- [x] Pydantic (or whichever exporter is chosen) is a dev dependency only; `snacker build` doesn't need it at runtime unless ticket 15 says otherwise.
- [x] PRD §7.2's "indicative" shapes are replaced by a pointer to the schemas.

## Comments

- 2026-10-19: Implemented, with one change to the plan.
  - **One schema, not one per file:** `contract/static-json.schema.json` holds every file document and shared row under `$defs`. Separate files would each repeat the shared rows, which would make generating frontend types (ticket 16) produce duplicate declarations. PRD §7.2 maps each file path to its document.
  - **Generation:** `snacker schema --out …` uses pydantic's `TypeAdapter.json_schemas` over the contract TypedDicts. It is strict (`additionalProperties: false`, every field required), uses field docstrings as descriptions, and leaves out per-field titles.
  - **Validation:** a `check` module walks a data directory, works out each file's document from its path, and validates it with `jsonschema`. Files it doesn't recognise are flagged too.
  - **Dependencies:** pydantic, jsonschema and types-jsonschema are dev dependencies for now. Ticket 15 decides whether they move to runtime.
  - **Tests:** the committed schema matches the generated one. A fixture build covering a URL code, a location with a space, an unknown product, and scanners with and without a last scan has no violations. The schema rejects a wrong null, an extra field, a missing nullable field, and a missing period.
  - **Real data:** 3,466 files, no violations.
  - Build test helpers moved to `tests/built_output.py`, and the fixtures to `tests/conftest.py`.
