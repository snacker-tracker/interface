# 13: Publish JSON Schemas for the output and validate every built file

**What to build:** The shapes of the static JSON become machine-readable. JSON Schema files, one per file type, are generated from the contract module (ticket 12) and committed at the repo root, so anything outside the backend (the frontend, a future Dagster job) can read the contract without reading Python. The fixture build is validated against them file by file. Requested 2026-10-19.

**Blocked by:** 12 (Gather the output contract into one backend module).

**Status:** ready-for-agent

- [ ] A backend command writes one JSON Schema per file type (meta, locations, index, scanners, product, code scans), with shared rows as reusable definitions and field docstrings carried into descriptions.
- [ ] The committed schemas are regenerated by that command; a test fails when they are out of date with the contract types.
- [ ] Schemas are strict: required fields are required, nullable fields are explicitly nullable, and unexpected fields are rejected.
- [ ] A build test validates every file written by the fixture build against its schema, including a URL-like code, an unknown product (`product: null`) and a scanner with no last scan.
- [ ] Pydantic (or whichever exporter is chosen) is a dev dependency only; `snacker build` doesn't need it at runtime unless ticket 15 says otherwise.
- [ ] PRD §7.2's "indicative" shapes are replaced by a pointer to the schemas.
